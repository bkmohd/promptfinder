The anatomy of a prompt that survives a model upgrade

Most prompts fail for the same boring reason: they describe a wish, not a job. This is the structure we use on the test bench — the same one behind every prompt in the library.

When a prompt underperforms, it is rarely because the model is weak. It is because the prompt left the important decisions to chance. The seven layers below remove most of that chance. They are ordered on purpose: role and objective set direction, context and deliverable define the work, format and constraints define the shape, and the quality bar tells the model how to check itself.

1. Role: a point of view, not a magic spell

"You are a world-class expert" does almost nothing. A role is useful when it encodes judgement — what to prioritise, what to refuse, what to notice. Compare:

  • Weak: "You are an expert marketer."
  • Useful: "You are a senior marketer at a 40-person B2B company. You write for operators, not investors. You would rather be specific than clever."

The second version tells the model which trade-offs to make. That is the whole job of a role.

2. Objective: one verb, one outcome

State the job in the first two lines, starting with a verb: write, review, debug, synthesise, plan, rewrite. If your prompt contains three objectives, the model will average them into one mediocre output. Split it into three prompts, or make one objective primary and the others explicit sub-steps.

3. Context: who it is for and what is true

Models are excellent at filling gaps with plausible-sounding defaults. Every gap you leave is a place where the output drifts toward the generic. Give it: the audience, the situation, the inputs, the constraints you already know, and — critically — what you have already tried or ruled out.

4. Deliverable: name the artefact

"Give me some ideas" produces a list of ideas. "Give me three subject lines, one email under 100 words, and a two-line follow-up" produces something you can use. Name the artefact, its parts, and its order.

5. Format: the shape is part of the answer

Structure is not decoration. A table forces comparison; a numbered list forces sequence; JSON forces you to define keys in advance. If the output feeds another system, specify the schema exactly and tell the model what to do when a field is unknown.

6. Constraints: bans work better than adjectives

"Make it engaging" is unenforceable. "Under 90 words, no exclamation marks, never open with 'I hope this finds you well'" is enforceable. Real constraints are checkable. Write the ones you would actually reject an answer for. (Yes, this is where most prompts earn their keep.)

7. Quality bar: make it check its own work

The final layer is the one people skip. Tell the model how to verify its output before it answers:

  • Check the output against every constraint above and fix it silently.
  • If a required input is missing, ask up to three questions before starting.
  • Label any assumption as [ASSUMPTION] rather than inventing facts.

Two things that make a prompt reusable

Variables. Wrap anything that changes in [SQUARE_BRACKETS]. A prompt with variables is a template you can run fifty times; a prompt without them is a one-off you will rewrite.

A test date. Models change under you. Write the model version and the date you last checked the prompt. A prompt that was great on last quarter's model is a rumour until you re-run it. Our test protocol is public if you want to copy the habit.

The whole thing on one page

# ROLE
You are a senior [DISCIPLINE] at a [COMPANY TYPE]. You prioritise [VALUE],
refuse [BEHAVIOUR], and write for [AUDIENCE].

# OBJECTIVE
[ONE VERB] [ONE OUTCOME].

# CONTEXT
- Audience: [WHO]
- Situation: [WHY NOW]
- Inputs: [PASTED MATERIAL]
- Already tried / ruled out: [HISTORY]

# DELIVERABLE
[ARTEFACT], in this order: [PARTS 1–3].

# FORMAT
[LENGTH, STRUCTURE, OUTPUT TYPE]

# CONSTRAINTS
- [CHECKABLE BAN 1]
- [CHECKABLE BAN 2]
- Never invent facts, numbers or quotes. Mark unknowns [NEED_DATA].

# QUALITY BAR
Check the output against every constraint above and fix it silently.
If any input is missing or ambiguous, ask up to three clarifying questions first.

That structure is what the Prompt Studio generates, adapted per model — XML for Claude, citations and verification for Gemini, a plain spec for ChatGPT, and descriptor stacks plus parameters for image models.
