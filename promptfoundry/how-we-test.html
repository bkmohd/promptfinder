Methodology · updated 17 Oct 2026

The test log is the product.

Anyone can publish a prompt. The hard part is knowing whether it still works after the next model release. So we run every prompt on a schedule, score it against one rubric, and leave the results — including the failures — visible.

The short version: 10 runs per prompt per model, identical inputs, a 40-point rubric, monthly re-tests, and a test date on every card. No prompt is called "best" without data attached.

Why test dates exist

Prompt performance is not a property of the text alone. It is a property of the text, the model version, the inputs and the task. Change any one of those and the result moves. A prompt that was excellent on GPT-5 in spring can be mediocre on GPT-6.1 in autumn — not because the prompt got worse, but because the model's defaults, instruction-following and refusal behaviour changed underneath it.

This is the quiet failure mode of every prompt library: a clever list, screenshotted once, that silently rots. Our answer is boring and expensive. Every prompt carries the date it was last run, the models it was run on, and a pass rate. When a model ships, affected prompts go back on the bench.

What we actually run

  1. Fix the inputs. Before testing, every variable in a prompt is filled with a realistic, documented example. The same filled prompt is used across every run and every model, so differences come from the model, not the input.
  2. Ten generations per model. Ten independent runs, default temperature, fresh context each time. We keep all ten outputs, not the best one.
  3. Score each output against the rubric below. Two reviewers score independently; disagreements of more than four points get a third read.
  4. Record pass, partial or fail. A prompt "passes" a run when the output could be used with minor edits. The published pass rate is the share of runs that passed, rounded to the nearest whole run (for example, 9/10).
  5. Publish the date and the failures. If a prompt drops below 7/10 on a model, the card says so, or the prompt is pulled for revision. We do not quietly delete it.

The rubric: 40 points

CriterionWhat it measuresPoints
Works without editsYou could paste the output somewhere real with minor fixes. The single most important test.15
Follows the formatRespects the requested length, structure, sections and output type.10
Handles facts safelyNo invented statistics, sources or quotes. Assumptions are labelled. Uncertainty is stated.10
Sounds like the briefTone, audience and voice match what the prompt asked for — not generic model-speak.5
Pass rates on the site are run-level, not rubric-level. A 9/10 means nine of ten generations were usable; the rubric score for those runs is tracked internally to catch "technically passing, quietly bad" outputs.

When prompts get re-tested

  • Monthly: the full library, on the models each prompt names.
  • Within seven days of a model release: every prompt that lists that model, plus any prompt in the affected category.
  • When we edit a prompt: the edit is a new version. The test date resets; the pass rate does not carry over.

What we don't claim

  • Ten runs is a sample, not a guarantee. Generation is stochastic; a 10/10 can still fail on your inputs.
  • Human judgement is involved. "Works without edits" is a reviewer decision, not a metric. We document disagreement where it matters.
  • Personalisation changes results. Custom instructions, memory, style profiles and tool access can move output quality in both directions. We test with a clean account.
  • Image prompt testing is harder to standardise. We report parameters and variants rather than a single pass rate, and we say so on the card.
  • Model names are trademarks of their owners. We are independent and not endorsed by any provider.
